Every fleet command and option, as fleet help lists them. Commands that read only change nothing. The others write to this host, to the config repo or to other hosts, so run them when you mean to.

Add --json to a command for one JSON document on stdout. It always has ok, code, host and messages, and each command adds its own fields, listed under it below.

Options for every command

  • --json: Print one JSON document on stdout.
  • --help: Show this list.

fleet status

Reads only. It changes nothing.

Report this host: fleet clone, applied state, timer, pending changes, conflicts and tool versions (--all asks every host over ssh; --conflicts lists this host's conflicts in full, reading only).

fleet status [--all | --conflicts]

Options

  • --all: Ask every host over ssh.
  • --conflicts: List this host's conflicts in full, reading only.

JSON. Adds repos, applied, timer, schedule, pending, conflicts, conflictList, agents, notInstalled and tools. With --all, also hosts: one record for each host, with its result and its status. With --conflicts, only conflicts: a list of {kind, path, detail, fix}.

fleet doctor

Changes things. It writes to this host, to the config repo or to other hosts.

Start this host's MCP servers and ask each what it offers and how large its tool definitions are (saved as this host's doctor result), plus cheap local checks (--all asks every host over ssh). It runs the catalog's commands with real credentials and may make npx download packages, so it runs only when you ask for it, never from the timer.

fleet doctor [--all] [--timeout <seconds>]

Options

  • --all: Ask every host over ssh.
  • --timeout <seconds>: Give each MCP server this long to answer, from just above 0 to 600 (default 30).

JSON. Adds checks and servers. With --all, also hosts: one record for each host, with its result and its doctor fields.

fleet context

Reads only. It changes nothing.

Show how much each agent on this host loads before the first prompt (instructions, skill descriptions, MCP tool definitions), as bars and an estimate in tokens, with the largest items (--all asks every host over ssh and draws all bars on one scale). MCP sizes are the ones the last doctor run saved; it starts no server and reads no secret.

fleet context [--all]

Options

  • --all: Ask every host over ssh.

JSON. Adds agents and notes. With --all, also hosts: one record for each host.

Guide. The bridge: startup context

fleet diff

Reads only. It changes nothing.

Show what apply would change, without changing anything.

fleet diff

JSON. Adds created, updated, removed, forgotten, unchanged, warnings, conflicts and timer. They list what apply would do.

fleet bridge

Changes things. It writes to this host, to the config repo or to other hosts.

Open the full-screen view of every host, the matrix of what each gets, conflicts, timeline, secrets and catalog (--view opens on a screen, --host selects a host on it). It reads until you ask for more: P pushes after you type push, d runs doctor after you confirm (it starts real MCP servers). Needs a terminal.

fleet bridge [--view <screen>] [--host <name>]

Options

  • --view <name>: Open on this screen (home, matrix, conflicts, timeline, secrets, catalog, push, context).
  • --host <name>: Select this host on that screen.

JSON. --json is not available for this command.

Guide. The bridge

fleet ui

Changes things. It writes to this host, to the config repo or to other hosts.

Open a page in your browser that shows this host and can push, served from this process on 127.0.0.1 and guarded by a random token in the URL it prints. It stops on ctrl-c, or after 10 minutes with no page open. Not for agents; no --json.

fleet ui [--port <n>] [--no-open]

Options

  • --port <n>: Listen on this port (default: a free one).
  • --no-open: Print the URL and do not open a browser.

JSON. --json is not available for this command.

Guide. The page

fleet card

Changes things. It writes to this host, to the config repo or to other hosts.

Write fleet-card.svg (1200 x 630) here: an image of your fleet to share, with its counts, each host with its agents and OS, and a year of changes. Hosts are named host 1, host 2 unless --names; no server, skill, source or secret name is ever on it. --style picks machines (the default) or map; --badge writes a small fleet-badge.svg for a README instead. It reads what fleet last saw of each host and asks none.

fleet card [--style machines|map] [--names] [--badge]

Options

  • --style <name>: Machines (default) or map.
  • --names: Show the real hostnames, not host 1, host 2.
  • --badge: Write fleet-badge.svg, a small badge for a README.

JSON. Adds file, style, names, machines, agents, skills, mcpServers, changes, pushes, since and grid.

fleet apply

Changes things. It writes to this host, to the config repo or to other hosts.

Make this host match its config.

fleet apply

JSON. Adds created, updated, removed, forgotten, unchanged, warnings, conflicts and timer.

fleet push

Changes things. It writes to this host, to the config repo or to other hosts.

Publish changes to GitHub, then apply on every host (-m sets the commit message; --host applies only on that host: this one or one with an ssh destination, after publishing as usual).

fleet push [-m <message>] [--host <name>]

Options

  • -m <message>: Set the commit message.
  • --host <name>: Apply only on this host.

JSON. Adds hosts: one entry for each host, with its result, changes, conflicts, created, updated and removed. A conflict on this host also adds a top-level conflicts.

fleet undo

Changes things. It writes to this host, to the config repo or to other hosts.

Revert the last recorded push, or a named one, and push the revert to the same scope (--no-push stops after the revert commit; --yes skips the prompt).

fleet undo [--no-push] [--yes] [<commit>]

Options

  • --no-push: Stop after the revert commit.
  • --yes: Skip the prompt.

JSON. Adds commit (the push that was reverted), reverted and pushed. When the revert was pushed, also the push's hosts.

fleet capture

Changes things. It writes to this host, to the config repo or to other hosts.

Turn the MCP servers and skills this machine has, and the config does not, into config: on a terminal it asks about each (add for this host, add for every host, ignore, or take over one that already matches), then writes and commits the config and asks before it pushes. Reads only this machine; a value that becomes a secret goes to sops and is never printed. Without a terminal it only reports what it found.

fleet capture [mcp|skill <name> --host|--all|--ignore] [--yes] [--no-push]

Options

  • --host: Capture the named item for this host only.
  • --all: Capture the named item for every host.
  • --ignore: Stop listing the named item on this host (it is added to unmanaged in the host file).
  • --yes: Capture every item the way the defaults say (this host, a secret for each key named like one) and push without asking.
  • --no-push: Stop after the commit.

JSON. Adds items (what was found: kind, name, state, message, agents, variants with the names of env variables and headers and never a value), differs, unmanaged and notes. It writes nothing unless --yes, or an item with --host, --all or --ignore, is given; then it adds captured, commit, files, takenOver, rewrites and pushed, and the push's own fields when it pushed.

Guide. Capture

fleet adopt

Changes things. It writes to this host, to the config repo or to other hosts.

Record an existing MCP server or skill as fleet's.

fleet adopt mcp|skill <name>

JSON. Adds adopted, left and conflicts.

fleet secrets

Changes things. It writes to this host, to the config repo or to other hosts.

Edit, set, rekey or rotate encrypted secrets (rotate replaces values one by one with hidden input, after a leaked token, a rejected one or a removed host; it needs a terminal).

fleet secrets edit <file> | set <file> <NAME> | rekey | rotate [NAME...]

JSON. rekey adds rekeyed, the secrets files that were updated. edit and set add nothing. rotate has no --json form: it asks for each value on a terminal.

Guide. FAQ: where do my secrets end up?

fleet host

Changes things. It writes to this host, to the config repo or to other hosts.

Retire a host: delete its host file and secrets file, re-encrypt the secrets files without its key, commit and push, stop its timer over ssh if it answers and you agree, then offer to rotate the secrets it could read (without a terminal it needs --yes, and rotates nothing).

fleet host remove <name> [--yes]

Options

  • --yes: Remove the host without asking, and stop its timer there if it answers.

JSON. Adds removedHost (the name, or null when nothing was removed), committed, pushed, rekeyed, readable (the secret names the host could read, shared and own), timer (state and message) and, when rotated, rotation.

Guide. Retiring a machine

fleet skills

Changes things. It writes to this host, to the config repo or to other hosts.

Move pinned skill sources to the head of their branch (--review shows what changed first, with anything risky flagged, and asks per source on a terminal; without one nothing moves unless --yes).

fleet skills update [--review] [--yes] [<source>]

Options

  • --review: Show what changed first, with anything risky flagged, and ask per source on a terminal.
  • --yes: Move the pins without asking.

JSON. Adds updated and unchanged: the sources that moved and the ones that did not. With --review, also reviews.

Guide. Getting started: reading a skill update before it moves

fleet update

Changes things. It writes to this host, to the config repo or to other hosts.

Move the pinned tool commit in fleet.yaml to the newest release, or to the head of its branch when track names one (nothing is committed or applied).

fleet update

JSON. Adds repo, track, from, to, updated and changes, plus release when track is releases.

fleet init

Changes things. It writes to this host, to the config repo or to other hosts.

Bootstrap a host and install its timer.

fleet init <host>

JSON. Adds what apply adds, plus steps, checklist, missingSecrets, conflicts, recipient and, when it made one, backup: the new age key.

fleet demo

Reads only. It changes nothing.

Try the bridge on made-up hosts in a throwaway sandbox; nothing real is touched (--shell gives a shell in the sandbox instead, with a printed tour). Without a terminal, or with --json, it walks the tour itself.

fleet demo [--shell]

Options

  • --shell: Give a shell in the sandbox instead, with a printed tour.

JSON. Adds sandbox and steps.
