Where do my secrets end up?

They are encrypted in secrets/ in your config repo. On apply, fleet decrypts the ones a machine needs and writes them in plaintext into the settings files of your agents, at mode 600, because the tools read them from there.

What if I lose the age key?

Nobody can read the secrets without a key that can decrypt them, and the key of the machine you work from is the only one that opens all of them. Keep it in your password manager.

Does fleet touch skills or settings it did not write?

No. It leaves other entries in ~/.claude/skills alone, and in a settings file it changes only the keys your config names. If something is already at a path fleet wants to write, that is a conflict, and fleet stops.

Why does fleet say an agent is not installed?

A machine gets the agents installed on it, and fleet found none of <agent> although it applied config for it on this machine earlier. (An agent that was never set up here is not mentioned, however much the config says about it.) It leaves everything of that agent alone until it is installed, and says so on each apply, diff and status. If the machine should not have the agent at all, name the agents it keeps in its host file: agents: [claude]. See setting up machines, which also covers removing an agent's config.

When does a change reach a machine?

fleet push applies it straight away on every machine with an ssh: line in its host file. Every machine also pulls and applies on its own timer, every 30 minutes by default, so one that was offline catches up. timer: in hosts/_defaults.yaml changes the schedule for every machine and in a host file for that one; timer: off leaves a machine to fleet push and manual applies, and apply installs, changes and removes the timer to match. A machine with no ssh: line gets changes only this way.

What does the install script do?

It checks for git and Node, clones the tool into ~/.local/share/fleet/fleet, and links fleet into ~/.local/bin. It uses no sudo and installs nothing else, and you can read it first. Running it again changes nothing.

How do I update fleet?

Your machines run the tool commit pinned in fleet.yaml, so a new version reaches them only when you choose to take it. fleet update moves the pin to the newest release and prints what changed; a major version is flagged, and its "You need to do" section is the one to read first. If track: in fleet.yaml names a branch instead of releases, it moves to that branch's latest commit. Read the output and git diff, then run fleet push.

Should I work in ~/.local/share/fleet/fleet?

No. That is the copy your machine runs, and fleet moves it to the pinned commit. To work on the tool, use a separate checkout and run its own bin/fleet.

Does it run on macOS?

Yes, macOS 12.3 or newer. The timer is a LaunchAgent instead of a systemd timer, and the scripts and tool search know Homebrew. See macOS.
