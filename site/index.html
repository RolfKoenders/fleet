How it works

Write it once. Every machine follows.

Your config is a git repo you own. fleet push publishes it and applies it on every host it can reach over ssh. Every machine also pulls and applies on its own every 30 minutes.

What it keeps in line

        
Everything your agents need. Nothing they shouldn't.

      

      

        

          

            
!

            
Conflicts, never overwrites

            
If a machine holds something different from your config, fleet stops and tells you exactly what and how to fix it. Hand edits and tool-written changes are never silently replaced.

          

          
✕ ~/.claude/CLAUDE.md is a file, not a link
  fix move it aside, then run fleet apply

        

        

          
≡

          
Shared instructions

          
One AGENTS.md and per-host rules, linked into Claude Code and opencode.

        

        

          
◆

          
Pinned skills

          
Skills from your repo or upstream sources, pinned to a commit and grouped into bundles per host.

        

        

          
⇄

          
MCP servers

          
One catalog, included or excluded per host. fleet doctor starts each one and checks it answers.

        

        

          

            
✓

            
Skill review

            
A skill is instructions your agent follows, so an update from someone else changes what it does. fleet skills update --review reads what a source would bring in before its pin moves: the commits, the skills you use that changed, and a flag for each new script, new URL or wider allowed-tools.

          

          

        

        

          

            
▤

            
Startup context

            
Before your first prompt, each agent has already loaded your instructions, the descriptions of your skills and the tool definitions of your MCP servers. fleet context draws that as bars, in estimated tokens, with every host on one scale, so you see which machine and which server weighs the most. It only reads files and starts no server.

          

          

        

        

          
⚿

          
Encrypted secrets

          
sops and age keep tokens encrypted in git. Each machine decrypts only what it is a recipient of.

        

        

          
↻

          
Self-healing

          
A systemd or launchd timer pulls and applies every 30 minutes, so machines you forgot about catch up.

        

        

          
⇉

          
Push over ssh

          
fleet push publishes, then applies on each host in turn and stops at the first conflict.

        

        

          
{}

          

            
Agent native

            
--json on every command, and fleet agent prints recipes so your agent can run it for you.

          

        

      

    


    
    

      

        
For Omarchy

        
Your fleet in the menu bar.

        
An Omarchy bar widget shows the health of every host in one icon, so you notice a conflict or an unreachable machine without opening a terminal.

      

      

        
        

          
    
            
  • One icon that is green when every host is ok, amber for a conflict or a stopped timer, red for a host that cannot be reached, with a count of the hosts that are not green.
    • 
            
  • A panel with a row for each host: its state, when it last applied, its timer and how many conflicts it has.
    • 
            
  • Shortcuts into the bridge: enter opens a host, c the conflicts, r checks now.
    • 
          

          
It runs only fleet status --all --json, which reads. Pushes and doctor stay in a terminal, behind fleet's own prompts. The screenshot shows made-up hosts.
